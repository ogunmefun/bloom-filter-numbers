# Final submission checklist

## Before starting

- [ ] All three members know their issues and agree on the schedule.
- [ ] Confirm instructor approval for the algorithm and revised number-search study.
- [ ] Confirm the algorithm was not already presented in class.
- [ ] Confirm deadline and submission method.

## Code — Dem checks, everyone contributes

- [ ] Include all three source files and run instructions.
- [ ] Generate exactly 1,000 integers in the inclusive range 2000–3000 for the main demo.
- [ ] Keep duplicates and report distinct count.
- [ ] Show a verified present query and a verified absent query.
- [ ] Use "possibly present" and "definitely absent" correctly.
- [ ] Check inserted values have no false negatives.
- [ ] Save reproducible results, seeds, timing methodology, and false-positive counts.
- [ ] Run successfully from a fresh download; include the required code listing.

## Paper — Renee checks, everyone writes

- [ ] Present algorithm, study, results, and analysis.
- [ ] Include actual measured results and appropriate citations.
- [ ] Explain duplicates, false positives, complexity, and limitations.
- [ ] Check DOCX and exported PDF; no more than 8 single-spaced pages.
- [ ] All three members review the final version.

## Presentation — Jacob checks, everyone presents

- [ ] All three members have 3 slides and about 4 minutes each.
- [ ] Show the algorithm, demo, measured results, and conclusions.
- [ ] Include the PowerPoint and PDF backup.
- [ ] Verify slides match the paper and raw results.
- [ ] Rehearse at 12 minutes; never exceed 15 minutes.
- [ ] Keep demo output as a backup and prepare for classmates' questions.

## Finish

- [ ] Each issue checklist is complete and peer-reviewed before closing.
- [ ] All required files are uploaded and easy to find.
- [ ] Submit through the instructor's required channel; a GitHub upload alone may not count as course submission.
